launchd persistence map · macOS

Boot
print

Mac の起動時に何が動き、どこに常駐しているのか。 launchd ジョブを 4 つのレーンに並べ、トリガー・署名・前回との差分・ 24 時間スケジュールを 1 枚で読む静的ビューアです。

デモを開く 仕組みを読む

Process Sentinel が「今」を見るのに対して、Bootprint は「これから動くもの」を見る。

WHY

起動と常駐は、見えない背景に集まる。

Mac の常駐プロセスは LaunchDaemons と LaunchAgents に分かれ、 system / global / GUI / user のドメインで動きます。ラベルだけの一覧では、 どこに置かれ、何をきっかけに動き、誰が署名したのかが別々の場所に散らばります。

Bootprint は launchd の plist と launchctl の実行状態を JSON に正規化し、 ブラウザで 4 つのレーンに描き直します。検知エンジンではなく、 読む順番を組み立てるための地図です。

HOW IT WORKS

収集・正規化・可視化を、静的な仕組みで。

ネイティブアプリや常駐エージェントは作りません。macOS 標準の plutil / launchctl / codesign でスナップショットを取得し、 JSON にまとめてブラウザへ渡します。サーバーもデータベースもビルド手順も不要です。

01 / COLLECT

plist と実行状態を集める

5 つの plist ディレクトリを走査し、plutil で解析。launchctl print で loaded / PID / 終了コード / disabled を突き合わせます。

02 / NORMALIZE

事実だけの JSON に整える

トリガーを RunAtLoad / KeepAlive / 間隔 / カレンダー / 監視に正規化。codesign で署名と Team ID を確認し、トークン様の引数はマスクします。

03 / VISUALIZE

地図として読む

ブラウザ側で状態とスコアを計算し、レーン・ベンダー・24h リボン・差分・インスペクタを描画。表示状態は URL に載ります。

FEATURES

一枚の地図で、常駐の輪郭をつかむ。

L

4 レーンの永続化マップ

System / Global / GUI / User の配置場所ごとに並べ、第三者ジョブはベンダー単位でまとめます。Apple は初期状態で折りたたみ。

T

トリガーの翻訳

ログイン時・常駐・定刻・間隔・パス監視をタグと 24h リボンで表示。RunAtLoad と KeepAlive の違いをその場で読めます。

S

署名とスコア

未署名・アドホック署名・Team ID を表示。実行パスの書き込み可否と組み合わせ、Error / Warning の理由を列挙します。

D

ベースライン差分

domain:label をキーに、新規・変更・消滅を判定。前回から増えた常駐をフィルタなしで発見できます。

C

24 時間スケジュール

カレンダー起動と間隔起動を同じ時間軸に重ね、1 時間未満の高頻度実行はストライプの帯で表現します。

U

URL に載る状態

状態・レーン・トリガー・検索・選択中ジョブをクエリに保存。気になった常駐をそのまま共有できます。

STATUS MODEL

4 つの状態と、その決め方。

分類はブラウザ側の純粋関数で行い、スナップショットには生の事実だけを持たせます。 判定順は「未署名・危険パス → 警告条件 → システム領域 → 健全」。

状態条件の例表示
Error 実行ファイルなし、signed: false かつ書き込み可能領域、/tmp・/Users/Shared からの実行 赤いカード。スコア最大 100。アラート最上位。
Warning 未署名、アドホック署名、署名不明、60 秒未満の高頻度実行、新規出現、定義変更 琥珀色。スコアと理由を表示。
Healthy 署名済みで、危険パス・高頻度・差分のいずれにも該当しない ミント色。静かに一覧に残る。
External com.apple.* または /System・/usr/libexec などのシステム領域 青灰色。スコアは 0 に固定し、ノイズを抑える。

状態は危険度の断定ではなく、見る順番を決めるためのシグナルです。最終判断は plist・実行パス・署名・トリガー・差分を並べて行います。

DEMO

公開デモは、40 件の合成ジョブ。

実在の macOS ジョブを模しつつ、危険な組み合わせと差分が一目で分かるように構成しています。 未署名で書き込み可能領域から動く com.example.helper、 アドホック署名の homebrew.mxcl.ollama、前回から消えた com.example.legacy など。

QUICK START

手元の Mac で試す。

デモは合成スナップショットです。実データを見るには、リポジトリ直下でコレクタを実行してからビューアを開きます。

1 · collectPython 3 · macOS
# リポジトリ直下で
python3 Bootprint/tools/collect_launch_jobs.py

# 前回のスナップショットを baseline に残す
python3 Bootprint/tools/collect_launch_jobs.py \
  --baseline Bootprint/viewer/data/jobs_baseline.json

# 署名確認を省略して速く取る
python3 Bootprint/tools/collect_launch_jobs.py \
  --no-codesign
2 · viewstatic
# 静的サーバーを起動
python3 -m http.server 8000

# ブラウザで開く
http://localhost:8000/Bootprint/viewer/

# 別のスナップショットを指定
...viewer/?data=jobs_snapshot.json
           &baseline=jobs_baseline.json

# 未署名だけを共有する
...viewer/?unsigned=1

コレクタは読み取り専用です。ジョブの load / unload / enable / disable / 削除は行いません。 環境変数はスナップショットに含めず、トークン様の引数は [REDACTED] に置き換えます。

SCOPE

これは何で、何ではないか。

launchd の「読む順番」を作る

配置場所・ベンダー・トリガー・署名・差分を 1 画面に寄せ、確認したい常駐へ 30 秒で辿り着けるようにします。

検知エンジンではない

マルウェア判定や自動削除はしません。イベントの常時監視ではなく、スナップショットを読む静的プロトタイプです。

v1 は launchd に集中

ログイン項目 / BTM / System Extensions は未対応。Phase 4 以降の拡張候補です。

デモは合成データ

公開デモのホスト名・PID・パス・Team ID は実在の macOS を模した合成値です。実データはローカルで生成します。
