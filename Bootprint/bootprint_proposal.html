Boot
print

起動のたびに、何が動き出すのか。macOS の launchd ジョブを、 ドメイン・ベンダー・トリガー・署名の関係として一枚の地図に描く試作提案です。

2026年11月 対象: macOS 構成: 静的ビューア + ローカルコレクタ

01

コンセプトと狙い

macOS では launchd が PID 1 として起動し、システムデーモンとユーザーエージェントを管理します。 アプリを閉じても、再起動しても、あるいは一定間隔で、ジョブは静かに動き続けます。 しかし launchctl list はフラットな一覧で、plist は複数のディレクトリに散らばり、 トリガーと署名は別々の場所にあります。

Bootprint は、ジョブの定義（plist）と実行状態（launchctl）を収集し、 ドメイン・ベンダー・トリガー・署名の関係として可視化します。 「いま何が動いているか」を扱う Process Sentinel に対して、 「次に何が動き出すか」を扱う姉妹プロジェクトです。

見つける

見慣れない常駐

未署名、ユーザー書き込み可能領域、過剰な KeepAlive。単独ではなく組み合わせで候補を浮かび上がらせます。

理解する

起動の順番

ログイン時、カレンダー、一定間隔、パス監視。いつ・何が起点で動くのかを時間軸で読みます。

比べる

前回との差分

新しいジョブ、消えたジョブ、トリガーが変わったジョブ。ベースラインとの比較で変化を追います。

02

Process Sentinel からの連続性

03 の Process Sentinel は「現在のプロセス」を親子ツリーで描きました。 Bootprint は同じ macOS の層を、起動・永続化という時間方向へ延長します。 データの持ち方と画面の作法は共通です。

プロジェクト対象構造状態
01 Pipeline Viz データ処理パイプライン ステップの流れ レイテンシ・件数・エラー
03 Process Sentinel 現在のプロセス 親子ツリー CPU・メモリ・署名・接続
04 Bootprint 起動・常駐ジョブ レーン × ベンダー トリガー・loaded・終了コード・署名
共通する設計原則: 生の事実だけを JSON に置き、状態・スコア・差分はブラウザ側で計算する。 これにより、判定ルールを変えてもスナップショットを作り直さずに済みます。
03

全体アーキテクチャ

常駐エージェントもデータベースも作りません。macOS 標準の launchctl と plutil、 codesign でスナップショットを採り、静的ファイルとしてブラウザへ渡します。

collect plist + launchctl

LaunchAgents / LaunchDaemons を探索し、plutil で JSON 化。launchctl から loaded / PID / 終了コードを取得。

→
normalize jobs_snapshot.json

ジョブを domain:label で一意化。トリガーを正規化し、署名と秘匿情報のマスクを付与。

→
visualize model.js → viewer

分類・スコア・差分・スケジュールを計算し、永続化マップ・24h リボン・インスペクタに描画。

05

収集方法とプライバシー

コレクタは collect_launch_jobs.py 1 本です。Python 3 以外の依存はありません。 plist を定義の正とし、launchctl の実行状態を重ねます。

discover

plist の探索

/System/Library/LaunchDaemons、/System/Library/LaunchAgents、/Library/LaunchDaemons、/Library/LaunchAgents、~/Library/LaunchAgents。

state

実行状態の取得

launchctl print system / gui/$UID / user/$UID と launchctl list。loaded、PID、最後の終了コードを突き合わせます。

signature

署名の確認

codesign -dv --verbose=2 を実行パス単位でキャッシュ。Team ID とアドホック署名を記録します。

redact

秘密情報のマスク

EnvironmentVariables の値と、--token 系の引数を既定で伏せます。公開デモは合成データのみです。

マージ規則

  • Disabled は launchctl print-disabled の上書きを優先し、なければ plist の値を使う。
  • 同じ label が複数ドメインに存在する場合は domain:label で別ジョブとして扱う。
  • ProgramArguments しかない場合は先頭を実行パスとして扱い、残りを引数にする。
  • 署名や実行状態が取れない場合は null。推測値は入れない。
マスクの限界: 引数や環境変数に含まれる秘密情報を完全に検出することはできません。実スナップショットを公開しない運用を前提にし、 コレクタはローカル保存を既定にします。
06

状態分類とスコア

常駐していること自体は危険ではありません。Bootprint は署名・実行場所・トリガーの組み合わせで 「先に見る候補」を決めます。判定はブラウザ側の純粋関数で行います。

状態主な条件表示
Error 実行ファイルが存在しない / 未署名かつユーザー書き込み可能領域 / /tmp・/Users/Shared 配下 赤。スコア最大 100。アラート最上位。
Warning 第三者で未署名またはアドホック / RunAtLoad + KeepAlive + 未署名 / 60 秒未満の高頻度実行 / 前回から変更 黄。理由とスコアを表示。
Healthy 署名済みで、通常のトリガーと実行場所 ミント。静かに一覧に残る。
External com.apple.*、/System・/usr/libexec など Apple 領域 青。スコアは 0 に固定し、ノイズを抑える。

スコアの加点例

シグナル加点補足
実行ファイル消失+50Error の主条件
未署名+40署名が false のとき
ユーザー書き込み可能領域+25ホーム、Application Support、共有領域など
アドホック署名+25Team ID なし
RunAtLoad+10起動時実行
KeepAlive+10終了しても再起動
60 秒未満の StartInterval+10高頻度実行
前回以降の新規出現+15ベースラインがある場合

スコアは 0–100 に丸め、Error → Warning の順、スコア降順でアラートに並べます。 最終判断は plist・実行パス・署名・トリガーを並べて行うための補助線です。

07

画面構成

中心は Persistence map。4 つのレーンにジョブカードを並べ、 第三者ジョブをベンダー単位でまとめます。Apple のジョブは初期状態で折りたたみ、 実データ 800 件超でも読める密度にします。

interaction

読む順番を設計する

検索、レーン、トリガー、未署名、差分で絞り込み。アラートをクリックすると該当カードへ移動します。Apple のジョブは「表示する」で展開します。

context

状態を URL に載せる

?job=gui%2F502%3Acom.example.helper&filter=unsigned のように選択とフィルタを共有。LIVE は 8 秒ごとに再取得します。

08

デモシナリオ

公開デモは 40 件前後の合成ジョブで構成します。実在の macOS ジョブを模しつつ、 危険な組み合わせと差分が一目で分かるようにします。

ジョブレーン状態見どころ
com.apple.WindowServersystemExternalApple 領域。スコア 0 でノイズを抑える
com.docker.vmnetdsystemHealthy署名済みの第三者デーモン
com.tailscale.tailscaledglobalHealthyKeepAlive でも署名済みなら静かに残る
homebrew.mxcl.ollamaglobalWarningアドホック署名 + RunAtLoad
com.example.helperguiError未署名 + 書き込み可能領域 + KeepAlive
com.example.syncguiWarning前回から StartInterval が変化
com.example.legacyguiRemovedベースラインだけに存在

レーンは plist の配置場所（System / Library / GUI agent / user agent）を表し、 launchd のドメイン（system / gui/502 / user/502）とは別に持ちます。 同じ label でも配置が違えば別ジョブとして扱います。

差分は +2 new / ~3 changed / −1 removed を初期状態にします。 「新しい常駐が増えた」ことが、フィルタを開かずに分かる構成です。

09

スコープと制約

v1 でやること

launchd の可視化に集中

  • plist の探索と正規化
  • loaded / PID / 終了コードの突き合わせ
  • 署名・トリガー・差分の表示
  • 読み取り専用。有効化・無効化はしない
v1 でやらないこと

検知エンジンにはしない

  • ログイン項目 / BTM / System Extensions
  • マルウェア判定や自動削除
  • イベントの常時監視（Endpoint Security）
  • Windows / Linux 対応
正直な限界: launchctl の情報は権限や macOS のバージョンで欠けることがあります。 Bootprint は「見つけるための地図」であり、見つけた後の判断を自動化するものではありません。

実装ロードマップ

Phase 1 — コレクタとスキーマ。 plist 探索、plutil 解析、launchctl 突き合わせ、署名確認、マスク。合成デモとベースラインを作る。
Phase 2 — モデルとテスト。 検証、分類、差分、トリガー解析、ベンダー grouping、URL 変換。Node テストを 20 件以上。
Phase 3 — ビューアと LP。 永続化マップ、24h リボン、インスペクタ、アラート、差分、レスポンシブ。GitHub Pages に公開。
Phase 4 — 将来。 ログイン項目 / BTM、起動シミュレーション、--watch による履歴、通知。必要になったら拡張する。

最初に動かす最小原型

  • 5 つの plist ディレクトリを走査し、JSON にできる
  • launchctl から loaded / PID を突き合わせられる
  • 未署名ジョブを Error として強調できる
  • 前回スナップショットとの差分を表示できる
11

成功条件

完成度の基準は「機能が多いこと」ではなく、読む順番が生まれることです。

  • デモを開いて 30 秒以内に未署名ジョブへ辿り着ける
  • ログイン時・定期・監視の違いを説明できる
  • 前回から増えた常駐を差分で発見できる
  • 実スナップショットで JSON 検証が通り、秘密情報が露出しない
  • 360px 幅で横溢れせず、コンソールエラーが 0
  • Process Sentinel と並べても、同じ設計思想だと分かる
12

まとめ

Bootprint は、macOS の起動と常駐を「見えない背景」から「読める地図」へ変える試作です。 Process Sentinel が現在を見るのに対して、Bootprint はこれから動くものを見ます。 事実を JSON に分離し、ブラウザで状態と差分を計算する構成は、そのまま小さく始められます。

次の一歩: まずはコレクタと合成デモを作り、40 件のジョブが意図どおり Error / Warning / External に分かれることを確認します。 その後、ビューアと LP を仕上げて公開します。
