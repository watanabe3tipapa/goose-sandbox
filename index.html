Pipeline Viz

データ処理工程を、生きた設計図に。Goose が出力する実行時メトリクスと oh-my-mermaid の Perspective 構造を接合し、パイプラインの流れ・健康状態・ボトルネックを一枚で把握するダッシュボード試作です。

このツールは何のためにあるのか

データ処理パイプラインは、ステップが増えるほど「いま何が起きているか」を把握するコストが急増します。ログを追い、メトリクスを突き合わせ、どのステップが遅いのか、どこでレコードが落ちているのかを推測する。Pipeline Viz は、その確認作業を図の上に引き寄せます。

Goose の低オーバーヘッドな計測と、oh-my-mermaid の構造化されたダイアグラムを組み合わせ、「構造」と「状態」を同じ枠組みで管理するのが本試作の狙いです。図は静的なドキュメントではなく、実行時メトリクスを反映するライブ・ビューになります。

Goose.omm/static

本試作が答えるのは、次の4つの問いです。

  1. いま、どのステップが動いているか

    各ステップのレコード数とレイテンシをライブ表示します。実行のたびに値が更新され、最終更新時刻も確認できます。

  2. どこで詰まっているか

    遅延の大きいステップを強調し、ステップ別レイテンシの内訳を表示します。クリックすると詳細パネルで入出力を確認できます。

  3. 前回から何が変わったか

    Diff モードで、前回スナップショットとのレコード数・処理時間の差分をノード上に表示します。

  4. エラーはどこへ隔離されたか

    検証に失敗したレコードは @error-handler に分岐します。隔離件数と最近のエラーを追跡できます。

使い方

  1. ダッシュボードを開く

    公開サイトの /viewer/ を開きます。ビルドやサーバーは不要です。ローカルで確認する場合は、リポジトリのルートで静的サーバーを起動します。

    python3 -m http.server 8000
# http://localhost:8000/viewer/

  2. サンプルデータを自分のパイプラインに差し替える

    viewer/data/metrics.json のステップ名・件数・時間・ステータスを変更します。取得に失敗した場合は、HTML 内の埋め込みサンプルで動作します。

    {
  "steps": [
    { "step_id": "Extract", "records_in": 1240, "records_out": 1240,
      "elapsed_ms": 46, "status": "Healthy" }
  ]
}

  3. GitHub Pages に配置する

    リポジトリのルートをそのまま公開するか、GitHub Actions でデプロイします。ルートの index.html が LP、viewer/ がダッシュボードです。相対パスのため、https://user.github.io/repo/ のようなサブパスでも動作します。

現在の制限

  • メトリクスはサンプル JSON とブラウザ内シミュレーションで、実際の Goose プロセスとは接続していません。
  • ライブ更新はポーリング方式です。SSE / WebSocket による配信は今後の実装対象です。
  • Mermaid の描画は独自の HTML / SVG 表現で、Mermaid ランタイムは読み込んでいません。ソース出力のみ対応しています。
  • 大規模ダイアグラムの仮想化や、複数パイプラインの同時監視は未対応です。
  • oh-my-mermaid 本体への組み込みは未実施で、UI とデータ構造の試作段階です。
