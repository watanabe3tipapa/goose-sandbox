Process Sentinel

Mac / iPhone / iPad 上の不審プロセスを、Pipeline Viz の流儀で「見える化」する次の実験プロジェク

01

背景と課題

あなたは、自分のデバイス（Mac、iPhone、iPad）に不審なプロセスが現出していないかを常に監視したいと考えています。 既存の Pipeline Viz は「データ処理パイプラインの構造と健康状態」を可視化する試作でしたが、次のステップとして、 「デバイス内部のプロセス群」という新しい対象に同じ可視化の発想を応用するのが自然な進化です。

監視対象

  • Mac: 起動中のプロセス、デーモン、エージェント
  • iPhone / iPad: アプリプロセス、バックグラウンタスク、ネットワーク接続
  • 共通: CPU / メモリの急激な変動、未知の署名なしバイナリ

可視化の要件

  • プロセス間の親子関係や依存関係を「流れ」として把握
  • 異常プロセスを色とパルスで即座に識別
  • 時系列で「いつから」不審な動きが始まったか追跡
  • Pipeline Viz と同じく、静的ドキュメントではなくライブ・ビュー
02

コンセプト：Pipeline Viz の進化形

Pipeline Viz の核は「ダイアグラム実行時メトリクスを反映するライブ・ビューとして扱う」ことでした。 Process Sentinel では、この発想をデバイス・プロセス監視に置き換えます。

つまり、Pipeline Viz で培った「構造と状態の同時可視化」を、 プロセスツリー × 異常スコア × 時系列 という新しいドメインに移植するのが、次のプロジェクトの中核です。

03

システムアーキテクチャ

3.1 収集層（Endpoint API）

デバイスごとにプロセス情報を取得するインターフェースを設計します。 Mac では ps、top、Endpoint Security API、System Extensions を組み合わせ、 iOS では制約の中で取得可能な範囲（ネットワーク拡張、VPN 関連、公開 API）を活用します。

層役割技術要素
収集層 プロセス一覧、CPU / メモリ、ネットワーク接続、コード署名の取得 macOS: ES API / libproc / ps
iOS: NEProvider / sysctl（制限あり）
正規化層 OS 間の差異を吸収し、共通スキーマに変換 Swift Codable / JSON Schema
検知層 ベースラインからの逸脱、未知バイナリ、急激なリソース消費をスコア化 ルールベース + 統計的閾値
可視化層 プロセスツリーをパイプライン風にレンダリング、リアルタイム更新 SwiftUI Canvas / WebView + Mermaid / D3
通知層 異常検知時のプッシュ通知、ログ記録 UserNotifications / OSLog

3.2 異常検知エンジン

ベースライン学習

通常時のプロセス一覧とリソース使用量を数日間記録し、統計的な「正常範囲」を自動構築します。

署名検証

コード署名の有無、チームID の変化、アドホック署名の検出を行い、未署名バイナリを即座にフラグします。

ネットワーク相関

未知プロセスが外部通信を開始した場合、相関スコアを上昇させ、視覚的に強調します。

04

ビジュアライゼーション設計

Pipeline Viz の「ノード色 + スループットバッジ」を、プロセス監視の文脈に再解釈します。

4.1 状態色の定義

状態色意味
Healthy #8ef0cf 署名済み、ベースライン内、通信パターン正常
Warning #ffc857 CPU / メモリの急上昇、稀なプロセスだが署名あり
Error #ef4444 未署名、未知バイナリ、異常な外部通信、親プロセスの不審な fork
External #b8dcff OS システムプロセス、常駐デーモン（常に存在する前提）

4.2 UI パターン

  • プロセスパイプライン・ビュー: 親子関係を水平フローで配置。Pipeline Viz の ETL ステップ表示を fork / exec チェーンに置き換えます。
  • 時系列ミニマップ: 各プロセスの CPU / メモリをスパークラインで表示。異常発生時点をドラッグで選択し、詳細にドリルダウン。
  • アラートサイドバー: Error 状態のプロセスを自動ピン留め。クリックで該当ノードにフォーカス＋周辺プロセスをハイライト。
  • Diff モード: 前回スキャンとの差分を表示。新規プロセスは緑の枠線、消失プロセスはグレーアウト、変更箇所はアニメーションで強調。
05

技術スタック

Mac クライアント

Swift SwiftUI EndpointSecurity Combine OSLog

SwiftUI でダッシュボードを構築し、Endpoint Security API または libproc.h 経由でプロセス情報を取得します。Combine でデータストリームを統合し、リアクティブに UI を更新します。

iOS / iPad クライアント

Swift SwiftUI NetworkExtension BackgroundTasks CoreData / SwiftData

iOS のサンドボックス制約を考慮し、取得可能な情報に限定した「軽量版 Sentinel」を提供します。Mac 側と共通の可視化コンポーネントを再利用します。

可視化エンジン

SwiftUI Canvas MermaidJS D3.js SVG

ネイティブ描画と Web ベース描画のハイブリッドを検討します。Pipeline Viz で Mermaid を使った知見を活かしつつ、より動的なノード配置には Canvas / D3 を併用します。

データ層

SQLite GRDB.swift JSON CloudKit (opt)

ローカルに時系列データを蓄積し、ベースライン学習と履歴参照を可能にします。複数デバイス間の同期が必要な場合のみ CloudKit を選択的に利用します。

06

実装ロードマップ

Phase 1 — プロセス収集プロトタイプ（Mac）

ps または ES API を使い、プロセス一覧と基本メトリクスを取得し、JSON 形式で出力できることを確認します。Pipeline Viz の metrics.json と同じ発想でprocess_snapshot.json を設計します。

Phase 2 — ベースラインと異常検知

数日間のプロセスログを蓄積し、統計的ベースラインを構築。未知バイナリ検出と CPU / メモリの閾値超過をルールベースで実装します。

Phase 3 — Sentinel Viz ダッシュボード

SwiftUI または WebView でプロセスツリーをパイプライン風に描画。異常ノードの色反映とパルスアニメーションを実装します。Pipeline Viz の viewer/ をフォークして拡張するのも有効です。

Phase 4 — iOS 軽量版と通知

iOS で取得可能な情報に絞ったビューを築し、異常検知時のプッシュ通知を実装します。Mac と UI コンポーネントを共有します。

Phase 5 — Diff / Alert / 履歴

前回スキャンとの差分表示、アラートサイドバーの自動ピン留め、時系列のスパークライン表示を追加します。Pipeline Viz の Diff モードをそのまま応用できます。

07

Pipeline Viz からの連続性

次のプロジェクトは Pipeline Viz を否定するのではなく、対象ドメインを「データパイプライン」から「デバイス・プロセス」に拡張します。 以下の資産をそのまま再利用できます。

  • .omm/ ディレクトリ構造: プロセスカテゴリ（system / user / network / unsigned）を Perspective として管理できます。
  • ライブメトリクス連携: live_metrics_url のポーリング / SSE 機構を process_snapshot.json 向けに流用できます。
  • 状態色と classDef: Healthy / Warning / Error / External の4色体系は、プロセス監視にもそのまま適合します。
  • Diff & Alert UI: 前回実行との差分比較、Error 時のサイドバー自動ピン留めを、プロセスの生死・変化追跡に応用できます。
  • GitHub Pages ホスティング: 静的プロトタイプ（viewer/）は goose-sandbox と同じワークフローで公開できます。

09

まとめ：次に考案すべきもの

次のプロジェクトとしては、「Process Sentinel」を提案します。 Pipeline Viz の可視化哲学を継承しつつ、監視対象をデバイス上のプロセスに切り替えることで、 あなたの「不審な動きを視覚的に捉えたい」というニーズに直接応えられます。

最初に作るべき最小原型

  1. Mac で ps または ES API からプロセス一覧を取得するスクリプト
  2. 取得結果を process_snapshot.json に正規化する Swift ツール
  3. その JSON を読み込み、プロセス名と PID をノードとして表示する SwiftUI / WebView ビューア
  4. 未署名プロセスだけを赤色で強調するフィルタ機能

この4つが動けば、Pipeline Viz からの橋渡しが完了し、本格的な異常検知エンジンへの拡張が始められます。
