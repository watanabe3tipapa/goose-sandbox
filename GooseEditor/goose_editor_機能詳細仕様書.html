01 リッチテキスト編集機能

Goose Editor は、WYSIWYG（見たまま編集）と Markdown ソース編集の両方をサポートします。ユーザーはいつでもモードを切り替えられ、一方の編集が他方に即座に反映されます。

1.1 サポートするブロック種別

ブロック種別説明Markdown 表現備考
Paragraph 通常の段落 連続したテキスト行 インラインスタイル対応
Heading 1〜6 見出し # 〜 ###### フォントサイズ階層あり
Unordered List 箇条書き（黒丸・ハイフン） - または * ネスト対応
Ordered List 番号付きリスト 1. 2. 自動採番・再採番
Code Block コードブロック ```lang 言語指定・シンタックスハイライト予約
Blockquote 引用ブロック > ネスト対応・複数段落を含む
Horizontal Rule 水平線 --- / *** 読み取り専用ブロック
Thematic Break 区切り線 --- 編集不可・キャレットは通過

1.2 インラインスタイル

スタイルMarkdown操作備考
Bold**text**Ctrl+B強調・太字
Italic*text*Ctrl+I斜体
Inline Code`code`Ctrl+`等幅フォント・背景色変更
Strikethrough~~text~~ツールバー打ち消し線
Link[text](url)Ctrl+KURL 入力ダイアログ

1.3 ロック操作

  • ブロック変換： キャレット行で Ctrl+0〜6 で見出しレベル切り替え、Ctrl+Shift+7 で番号付きリスト、Ctrl+Shift+8 で箇条書きリストに変換
  • ブロック移動： Alt+↑/↓ で現在のブロックを上下に入れ替え
  • ブロック分割・結合： 空行で Enter を押すと新規ブロック生成、Backspace で前のブロックと結合
  • インデント： Tab / Shift+Tab でリストのネストレベルを変更

Goose 実装上の注意： ブロックツリーの変更は「コマンドパターン」でラップし、Undo スタックに積みます。各コマンドは execute() / undo() の 2 メソッドを持つ構造体として実装し、Command[>..] グローイング配列で履歴を管理します。

02 Markdown 双方向変換

2.1 パーサ仕様

Markdown パーサは CommonMark サブセットに準拠し、Goose の u8[:] スライスを使ったゼロコピー解析を基本とします。

パースパイプライン

// パースパイプライン（3 パス構成）
fn parse_markdown(src: u8[:]) -> Document {
    var lines = split_lines(src);          // Pass 1: 行分割
    var blocks = parse_blocks(lines);       // Pass 2: ブロック境界検出
    var doc = parse_inlines(blocks);         // Pass 3: インライン解析
    return doc;
}

各パスの詳細

  • Pass 1（行分割）： \n / \r\n で分割。空行はブロック境界のマーカーとして保持
  • Pass 2（ブロック解析）： 行頭マーカー（#, -, >, ``` など）を検出し、ブロック境界を確定。ネスト構造（引用内リストなど）はスタックで管理
  • Pass 3（インライン解析）： 各ブロックのテキスト内で **, *, `, [ などのデリミタを走査し、InlineStyle 範囲を構築。デリミタの優先順位とネスト制限を CommonMark 準拠で処理

2.2 シリアライズ仕様

// Markdown シリアライザの出力例
fn serialize_markdown(out: u8[>..], doc: Document&) {
    for b in doc.blocks {
        match b {
            Heading { level, inlines } => {
                repeat_byte(out, '#', level);
                push_byte(out, ' ');
                serialize_inlines(out, inlines);
            }
            ListItem { bullet, inlines } => {
                let marker = if bullet { "- " } else { "1. " };
                append(out, marker);
                serialize_inlines(out, inlines);
            }
            // ...
        }
        push_byte(out, '\n');
    }
}

2.3 双方向同期戦略

モード A：WYSIWYG 優先モード（デフォルト）

  • ユーザーはリッチテキストで編集。内部ドキュメントモデルが真のデータソース
  • Markdown パネルは内部モデルを遅延シリアライズして表示（300ms デバウンス）
  • Markdown パネルは原則として読み取り専用。編集した場合は即座にパースして内部モデルを置き換え

モード B：ソース優先モード

  • Markdown ソースが真のデータソース。編集のたびにパースして WYSIWYG 側を更新
  • パースエラー時は WYSIWYG 側を前回成功状態のまま維持し、エラー位置をハイライト
  • 大きな文書ではパース負荷が高いため、ブロック単位の差分パースを検討

注意： 双方向変換で「ラウンドトリップの等価性」を完全に保証することは困難です（例：改行の扱い、HTML コメント、空行の数）。Goose Editor では「意味的等価性」を目標とし、表示上の差異は許容する方針とします。

03 自動保存と復元

3.1 保存戦略

Toolsmith Editor と同様に、データは端末内にのみ保存し、外部サーバーには一切送信しません。

ネイティブ版

  • 保存先： ユーザー指定のローカルディレクトリ内 .goose-editor/ フォルダ
  • ファイル形式： 各文書を {doc_id}.md として保存。メタデータは workspace.json
  • タイミング： 編集から 2 秒無操作後にトリガー、または Ctrl+S で即時保存
  • バックアップ： 保存前に {doc_id}.md.backup を作成。クラッシュ時に復元可能

ブラウザ版（WASM）

  • 保存先： Origin Private File System（OPFS）または IndexedDB
  • 容量： OPFS はブラウザの割り当て容量まで利用可能（localStorage の 5MB 制限なし）
  • 同期： File System Access API が利用可能な場合は、ユーザー指定のローカルファイルと直接同期

3.2 復元フロー

// 起動時の復元処理
fn restore_session() -> Workspace {
    let meta_path = get_config_dir() + "/workspace.json";
    if file_exists(meta_path) {
        let ws = load_workspace(meta_path);
        for doc_ref in ws.open_docs {
            let backup = doc_ref.path + ".backup";
            if file_exists(backup) && is_newer(backup, doc_ref.path) {
                show_recovery_dialog(doc_ref);   // バックアップが新しければ復元確認
            }
        }
        return ws;
    }
    return create_default_workspace();
}

3.3 保存状態インジケータ

  • ツールバー右端に「保存済み / 未保存」アイコンを常時表示
  • 未保存状態でウィンドウを閉じようとした場合、確認ダイアログを表示
  • 最終保存時刻をステータスバーに表示（例：「2 分前に保存」）

04 エクスポート機能詳細

4.1 Markdown エクスポート

  • 内部ドキュメントモデルを CommonMark 準拠のテキストに変換
  • 見出しの # 後には必ず 1 つの空白を挿入
  • リストのインデントは 2 スペース（または設定で 4 スペースに変更可能）
  • コードブロックの言語指定は元の情報を保持
  • 出力エンコーディングは UTF-8（BOM なし）

4.2 HTML エクスポート

// HTML テンプレート構造
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <title>{document.title}</title>
  <style>{embedded_css}</style>
</head>
<body>
  <article class="goose-document">
    {rendered_blocks}
  </article>
</body>
</html>
  • 各ブロックをセマンティック HTML タグにマッピング（<p>, <h1>〜<h6>, <ul>, <ol>, <pre><code>, <blockquote>）
  • インラインスタイルは <strong>, <em>, <code>, <del>, <a> に変換
  • 埋め込み CSS はシンプルなタイポグラフィ設定（フォント、行間、余白）のみ

4.3 JSON エクスポート

ドキュメント構造をそのまま JSON として出力。外部ツールとの連携やバックアップ用。

{
  "version": "1.0",
  "title": "ドキュメントタイトル",
  "blocks": [
    { "type": "heading", "level": 1, "inlines": [...] },
    { "type": "paragraph", "inlines": [...] }
  ]
}

4.4 Quarto エクスポート

  • YAML フロントマターを先頭に挿入（title, author, date, format など）
  • 本文は Markdown として出力し、Quarto レンダラにそのまま渡せる形式
  • コードブロックの言語指定は Quarto のコードセル属性に変換

4.5 Plain Text エクスポート

  • すべての Markdown 記号、HTML タグ、インライン装飾を除去
  • 見出しはテキストのみ出力（# 記号なし）
  • リスト記号も除去し、ネストは 2 スペースのインデントで表現
  • 用途：プレーンテキストへのコピー、文字数カウント、翻訳ツール連携

05 ワークスペース管理

5.1 文書管理

  • 新規作成： Ctrl+N。未保存の新規文書は「Untitled-1」などの一時名称
  • 開く： Ctrl+O。.md, .txt, .goose（JSON 形式）をサポート
  • 最近使った文書： 最大 20 件を履歴して保持。パスが無効な場合はグレーアウト表示
  • 複数文書の同時編集： タブバーで切り替え。未保存タブにはドットマーカー

5.2 フォルダツリー

  • 左サイドバーにフォルダツリーを表示。ワークスペースルート以下の .md ファイルを一覧
  • クリックで文書を開く。ドラッグアンドドロップでフォルダ間移動（ネイティブ版のみ）
  • フォルダの展開・折りたたみ状態はワークスペース設定に保存

5.3 ワークスペース設定ファイル（workspace.json）

{
  "version": "1.0",
  "root_path": "/home/user/documents",
  "open_docs": [
    { "id": "doc_001", "path": "notes/ideas.md", "cursor_block": 4, "cursor_offset": 12 }
  ],
  "active_doc": "doc_001",
  "sidebar_width": 240,
  "theme": "dark"
}

06 検索・置換

6.1 検索機能

  • ショートカット： Ctrl+F で検索バー表示
  • 検索対象： 現在の文書内のすべてのブロック・インライン対象
  • オプション：
    • 大文字小文字を区別 / 区別しない
    • 正規表現（サブセット：., *, +, ?, [], ()）
    • 全角半角を同一視するオプション
  • 結果表示： 一致箇所をハイライト、一致数をステータスバーに表示（例：「3 / 12」）
  • ナビゲーション： Enter / Shift+Enter で次・前の一致へ移動

6.2 置換機能

  • ショートカット： Ctrl+H
  • 単一置換： 現在の一致箇所のみ置換し、次の一致へ自動移動
  • すべて置換： 文書内のすべての一致を一括置換。操作前に確認ダイアログ
  • 正規表現置換： キャプチャグループを $1, $2 で参照可能

6.3 Goose 実装方針

struct SearchResult {
    block_idx: u32,
    inline_idx: u32,
    start: u32,
    end: u32
}

fn search_document(doc: Document&, query: u8[:], options: SearchOptions) -> SearchResult[>..] {
    var results: SearchResult[>..] = [];
    for bi, b in doc.blocks {
        for ii, inl in b.inlines {
            var pos = 0;
            while let m = find_next(inl.text, query, pos, options) {
                results.push(SearchResult { block_idx: bi, inline_idx: ii,
                                         start: m.start, end: m.end });
                pos = m.end;
            }
        }
    }
    return results;
}

07 Undo / Redo

7.1 コマンドパターンによる実装

すべての編集操作は「コマンド」としてカプセル化し、Undo スタックに積みます。Goose の enum.. を使い、コマンド種別ごとに異なるペイロードを持たせます。 

enum EditCommand.. {
    InsertText { block: u32, offset: u32, text: u8[varint] },
    DeleteText { block: u32, offset: u32, deleted: u8[varint] },
    ApplyStyle { block: u32, inline: u32, start: u32, end: u32, style: InlineStyle.. },
    RemoveStyle { block: u32, inline: u32, start: u32, end: u32, style: InlineStyle.. },
    InsertBlock { idx: u32, block: Block.. },
    DeleteBlock { idx: u32, block: Block.. },
    MoveBlock { from: u32, to: u32 }
}

struct History {
    undo_stack: EditCommand..[>..],
    redo_stack: EditCommand..[>..],
    max_size: u32   // デフォルト 500 コマンド
}

7.2 動作仕様

  • Undo： Ctrl+Z。undo_stack からポップし、inverse 操作を実行して redo_stack にプッシュ
  • Redo： Ctrl+Shift+Z または Ctrl+Y。redo_stack からポップし、元の操作を再実行
  • グループ化： 連続した文字入力（「あ」「い」「う」）は 1 つの「タイプセッション」としてグループ化し、Undo 時にまとめて巻き戻し
  • 上限管理： undo_stack が max_size を超えると、古いコマンドから破棄。メモリ使用量を一定に保つ
  • 新規操作時： ユーザーが新しい編集を行うと redo_stack はクリアされる

Goose の利点： EditCommand..[>..]（可変サイズ列挙型のグローイング配列）により、削除したブロックの内容も含めて履歴を 1 つの連続メモリ領域に保持できます。ヒープアロケーションなしで、Undo 履歴のシリアライズも容易です。

09 PWA / ブラウザ機能

9.1 インストールとオフライン動作

  • Web App Manifest： manifest.json でアプリ名・アイコン・テーマカラーを定義
  • Service Worker： 静的アセット（HTML, JS, WASM, フォント）をキャッシュ。初回アクセス後はオフラインで動作
  • ホーム画面追加： モバイルブラウザで「ホーム画面に追加」が可能
  • スタンドアロン表示： ブラウザ UI（アドレスバーなど）を非表示にしてネイティブアプリ風に動作

9.2 ファイルシステム連携

  • File System Access API： Chromium 系ブラウザで、ローカルファイルへの直接読み書きが可能
  • ファイルハンドルの保持： 一度開いたファイルのハンドルを保存し、次回起動時に自動再オープン（許可があれば）
  • ドラッグアンドドロップ： ブラウザウィンドウに .md ファイルをドロップして開く

9.3 クリップボード連携

  • コピー： 選択範囲を Markdown 形式でクリップボードに書き込み。他のエディタへ貼り付け可能
  • り付け： クリップボードの内容を Markdown としてパース。プレーンテキストの場合は Paragraph として挿入
  • HTML 貼り付け： リッチテキスト（Web ページなど）からの貼り付けは、HTML → Markdown 変換を試行

9.4 レスポンシブ対応

  • 画面幅 < 768px： サイドバーを自動折りたたみ、ツールバーをアイコン最小化
  • 画面幅 < 480px： Markdown ソースパネルを非表示（メニューから手動表示可能）
  • タッチ操作： ダブルタップで単語選択、長押しでコンテキストメニュー

10 UI / UX 設方針

10.1 レイアウト構成

+----------------------------------------------------------+
| [File] [Edit] [View]              [保存済み]  [検索 ▼]    |  <-- ツールバー

| ツリー    |                                               |

|           | Markdown ソース   | プレビュー               |  <-- オプション分割

10.2 デザイン原則

  • 最小主義： 必要な機能のみを表示。頻度の低い操作はメニューに格納
  • 視覚的階層： 見出しはフォントサイズと色で明確に区別。段落間に適切な余白
  • フィードバック： 保存状態、検索結果数、Undo 可否を常時表示
  • フォーカス重視： 編集領域以外の要素は低彩度で、文章に集中できる環境

10.3 テーマ

テーマ背景文字色アクセント用途
Dark（デフォルト）#0d1117#c9d1d9#58a6ff暗い環境・長時間執筆
Light#ffffff#24292f#0969da明るい環境・印刷確認
Sepia#f4ecd8#433422#8b6914目の疲労軽減・読書風

10.4 アクセシビリティ

  • キーボードナビゲーション： すべての機能をキーボードのみで操作可能
  • スクリーンリーダー： ブロック種別を ARIA ラベルで通知（「見出しレベル 1」「箇条書き」）
  • コントラスト： 本文テキストは WCAG AA 基準（4.5:1）以上を確保
  • フォントサイズ： 設定で 12px〜20px の範囲で変更可能
  • reduced motion： システム設定に連動し、アニメーションを無効化可能

Toolsmith Editor との差異 Goose Editor は元の「余計な選択肢を減らす」哲学を継承しつつ、キーボードショートカットとカスタマイズ性を追加します。ただし、設定項目は「テーマ・フォントサイズ・自動保存間隔・エクスポート形式」のみに制限し、複雑さを抑えます。
